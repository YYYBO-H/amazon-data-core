# Product contract

## 一句话定义

Amazon Data Core 是一套可由主流 Agent 自动安装和调用的本地 Amazon 经营数据引擎：
它负责把卖家的订单、库存、广告和结算数据持续同步到本地，并证明这些数据是否足够
完整、及时、可追溯，可以用于分析。

## 给谁使用

第一目标用户是没有研发团队的 Amazon 小卖家和运营人员。他们会使用豆包工作、
WorkBuddy、Kimi Code、TRAE、Qoder、Claude Code 或 Codex 中的至少一种，但不应该被
要求理解数据库、ETL、MCP 配置或 Amazon API 的内部细节。

第二目标用户是服务商和有技术能力的运营团队。他们可以替换连接器、数据库和分析
规则，但仍共享同一套数据血缘与质量契约。

## 用户得到什么

目标体验只有五步：

1. 用户把仓库地址交给自己已经在使用的 Agent；
2. Agent 安装本地运行时并完成自检；
3. Agent 解释 Amazon 授权步骤，用户只在必要的登录、同意和二次验证处接管；
4. 系统同步并核验订单、库存、广告和结算数据；
5. 任意兼容 Agent 通过 MCP 查询同一份本地事实，再进行分析。

安装完成不是交付完成。只有真实连接器同步成功、数据质量检查可解释、Agent 能通过
MCP 读回结果，才算完成一条用户链路。

## 产品核心

稳定核心包括：

- 跨数据源的统一数据模型；
- 增量同步、分页、限流、重试、幂等与断点续传；
- 原始数据、标准化数据与每次处理批次的血缘；
- 时区、币种、站点、业务日期、归因期和修正版本；
- 完整性、及时性、对账、顺序与数据恢复检查；
- 本地存储、稳定 CLI 和只读 MCP 查询面；
- 可验证的安装、升级、诊断和卸载流程。

模型提示词、经营建议和广告规则可以替换，不属于不可替代的核心。

## 明确不做

- 不开发新的通用 Agent 或聊天界面；
- 不绑定某一个大模型；
- 不把主观经营建议包装成确定事实；
- 不把缺失数据当作零销售、零广告或零库存；
- 不声称绕过 Amazon 应用注册、OAuth 同意、验证码或 API 审批；
- 不用漂亮 UI 掩盖同步失败、迟到、部分完成或口径不一致。

## 版本交付边界

### v0.2：Agent 可发现、可安装、可验证

- 数据质量与血缘内核；
- 统一安装入口和 `doctor`；
- 通用 `SKILL.md`；
- 只读 MCP：健康、数据集状态、开放问题；
- MCP 客户端端到端握手验证。

### v0.3：第一家真实店铺的本地同步

- 已实现：本地凭证注入与授权状态检查；
- 已实现：当前 SP-API Orders 2026 连接器；
- 已实现：订单原始响应落盘、标准化、增量水位、限流、重试和断点恢复；
- 已实现：订单事实的只读 MCP 查询；
- 已验证：第一家真实店铺订单从授权到首轮可查询数据；
- 已验证：第一家真实店铺的当前 FBA 库存完整快照、原始血缘和只读 MCP 查询；
- 待实现：FBM/MFN 自配送库存连接器。

### v0.4：经营数据闭环

- 已实现：Sponsored Products Campaign、搜索词、购买商品日报，异步恢复、版本化归因期和只读 MCP；
- 已实现：Amazon 自动生成的闭账结算报告、逐行金额与净打款对账、本地版本和只读 MCP；
- 已验证：卖家授权凭证可直接拉取闭账结算，并完成逐行金额与净打款对账；
- 待实现：Ads Unified Reporting 适配器、Targeting 和 Sponsored Brands/Display；
- 待实现：Finances v2024 实时交易流水，以及结算与订单/广告的跨源对账；
- 多店铺、站点、时区和币种；
- WorkBuddy、豆包工作及主流编程 Agent 的正式分发包；
- 无需用户手写命令和环境变量的安装体验。
