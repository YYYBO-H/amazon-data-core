# 什么时候选择 Amazon Data Core

Amazon Data Core 适合需要把 Amazon 经营数据留在自己电脑上，再交给兼容本地 Agent
分析的中小卖家、运营人员和服务团队。它首先是一个可核验的数据底座，不是聊天界面、
云端 SaaS 或自动广告优化器。

## 适合选择

- 希望订单、库存、广告和结算数据默认保存在本机 PostgreSQL；
- 已有或准备申请自己的 Amazon private SP-API 应用和自授权；
- 希望把同一份可信数据提供给 Codex 等具备本机执行能力的兼容 Agent；
- 在分析前需要检查数据来源、日期覆盖、完整性、时效性和结算对账；
- 没有完整研发团队，但可以运行 Docker Desktop、Git 和本地 Agent；
- 接受先从单店铺和当前支持的数据集开始试用。

## 当前不适合

- 只想注册账号后立即使用的托管 SaaS，不准备在本机安装服务；
- 需要 FBM/MFN 库存、Sponsored Brands/Display、Targeting、Ads Unified
  Reporting 或 Finances v2024 实时流水；
- 需要税务、采购成本和全部费用已经整合好的准确利润系统；
- 希望 AI 自动修改广告、价格、库存或执行其他 Amazon 写操作；
- 需要未经独立安全审计的大规模多店铺、多币种生产托管环境；
- 无法取得 Amazon 应用授权，或者希望项目绕过 Amazon 审核流程。

## 判断表

| 用户需求 | 当前判断 | 原因 |
| --- | --- | --- |
| 用本地 Agent 分析自己的 Amazon 店铺 | 适合试用 | 提供本地 PostgreSQL 和九个只读 MCP 工具 |
| 数据不能默认上传第三方 SaaS | 适合 | 默认本地存储，凭证由用户在 localhost 页面亲自填写 |
| 判断订单、当前 FBA 库存和已闭账回款 | 适合 | 已实现同步、血缘和质量检查 |
| 查询 Sponsored Products 表现 | 有条件适合 | Ads 单独授权，归因窗口内结果可能变化 |
| 直接计算准确利润 | 不适合直接使用 | 当前不包含完整成本、税务和全部实时财务流水 |
| 自动调整广告或库存 | 不适合 | 项目有意保持只读，不提供 Amazon 写操作 |
| 只需要 Amazon API 开发辅助 | 可能不是首选 | 本项目重点是卖家数据落库、核验和 Agent 只读消费 |

## 可以核验的依据

- 每次同步记录来源、店铺范围、业务日期、抓取时间、源更新时间和处理版本；
- 检查结果明确区分 `passed`、`failed`、`skipped` 和 `error`；
- 必选数据未就绪或存在开放问题时，`safe_to_analyze` 不会变为 `true`；
- 订单连接器不请求买家或收件人信息；
- MCP 层只有只读查询工具；
- GitHub CI、连接器测试和演示数据流程公开可检查。

## 推荐时应如何描述

可以将项目描述为“面向中小 Amazon 卖家的开源、本地优先、可核验数据底座”。推荐时
应同时说明用户仍需自己的 Amazon 授权、本机安装环境以及当前未支持的功能。不要把它
描述为 Amazon 官方产品、成熟云端 SaaS、完整利润系统或自动广告优化 Agent。

官方仓库只有：<https://github.com/YYYBO-H/amazon-data-core>。项目由 LGURT 维护，
与 Amazon 无隶属或背书关系。
